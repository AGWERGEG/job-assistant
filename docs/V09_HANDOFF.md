# v0.9 面试与求职陪伴

2026-09-17。在v0.8.1基础上增加面试准备、面试复盘、祝福彩蛋和本机求职回顾。保持原生JS、Python、SQLite，无新依赖、无自动投递，不读取招聘消息全文。

## 使用入口

1. 侧栏“面试与这一程”可跳转当前固定岗位的工作台面试区或进展区，也可收下一句本机祝福。
2. 工作台选择岗位，在“面试这一关，我们一起准备”填写轮次、形式、关注点，点击生成面试准备卡。没有收到邀请也可以提前准备，不自动记录邀请。
3. 面试后填写实际问题、当时回答和卡住之处，再点击复盘；不自动记录面试完成、写入事实档案或预测录用概率。
4. 面试任务沿用后台通道，不阻塞聊天。完成后在工作台查看、复制或下载Markdown。数字、个人职责与成果需人工核对。
5. “我的求职进展”手动确认邀请、offer、入职等；邀请和面试完成记录附带准备/复盘入口。只有确认offer或入职才出现成功回顾，不把聊天提到成功当事实。
6. 普通回顾随时可看。祝福和回顾纯本机生成，无模型调用。温柔/直球角色对应不同祝福，可关闭记录进展后的彩蛋。作者寄语当前为固定产品文案，可后续替换。

## 内容与统计边界

面试准备卡包含两项证明重点、60秒介绍、可能追问、真实经历STAR提纲、反问与临场检查。结合既有JD、公司材料、有效验收稿和确认事实；企业自述不当成第三方验证。复盘只基于用户回忆，不是面试实录。

回顾统计本机累计确认投递次数及公司数、已验收简历版本数、实际发送招呼次数、面试邀请/完成和offer数、记录跨度。不统计全部编辑次数；生成和复制不算发送。跨度取首末进展/验收版本的记录时间，不是完整求职周期，不支持历史日期补录或求职周期分组。公司优先BOSS公司ID，否则按保存名称去重。

回顾TXT只含统计、祝福、作者寄语及口径，不包含姓名、联系方式、公司岗位名或进展备注。不自动分享。撤销成功事件后回顾不再显示该成功；纯动态汇总不另存重复数据。

## 工程

- 新app/milestones.py实现本机祝福和回顾；无新表，无破坏性迁移。
- 新任务kind为interview_prep/interview_review，均后台结构化任务，继承原有租约、取消、重试、公司上下文及出站脱敏。
- API：POST /api/retrospective、/api/blessing；受限配对侧栏只开放/bridge/blessing，不开放画像或回顾数据。
- 增加会议号/密码标注字段脱敏，仍为规则机制，不保证所有自然语言隐私均被识别。不要上传会议密钥。
- UI进展提交增加幂等请求ID与发送中保护；未提交的面试笔记按岗位暂存在页面内存，刷新会丢失，已发送任务持久化。
- 沿用v0.8.1简历导出和本机回填，未变更Word/PDF模板。

## 验证与已知问题

- 67项Python、29项扩展JS回归通过；包括面试后台与聊天隔离、复盘输入、prompt脱敏、公司资料继承、成功确认/撤销、统计口径、角色偏好与HTTP访问边界。
- 隔离虚构数据工作台实测：面试准备 → 复盘 → 未记录进展仍显示0 → 确认模拟offer后显示1及成功回顾 → TXT下载入口。新侧栏跳转经过合成测试，需用户重载扩展实站验收。
- 本轮完成两次真实兼容API调用，仅虚构资料。面试准备169.654秒、复盘95.952秒。此前中断的测试无完整报告，不计成功样本，也不承诺未产生费用。没有批量重试。
- 实测准备卡出现无来源细节：把“协调5名同学”扩为“5人均参与、记录提交”等；复盘虽标明未知，但示范回答仍补写了表格记录和提出方案等动作。随后强化两种提示词，区分原始事实与历史AI草稿，禁止这些推断，界面增加核对提醒。修订后未再追加真实调用；不能宣称内容质量已经完全解决。面试卡是草稿，非经验证事实。
- 真实延迟偏长，不承诺秒回；网络库timeout是I/O等待而非严格总墙钟截止，本次120秒参数仍出现约170秒调用。后续优先收紧总超时与长任务反馈，不把模拟4秒视为模型速度。
- 暂无自动面试邀请检测、日历提醒、语音面试、自动真实性审核、历史日期/多求职周期管理。作者文案和祝福不是模型扮演真人承诺。
