# RC4.3.20 · SSE 推理内容分层与响应限额修复测试版

本版基于 RC4.3.19，修复 DeepSeek 等推理模型在结构化流式响应中因 `reasoning_content` 过长而误触发“模型返回过大”的问题。

## 修复内容

- 父进程现在把“已验证的流式能力”正确传给 API 子进程；结构化后台任务实际使用 SSE，而不是指标显示 stream、请求却仍非流式。
- SSE 按事件解析，支持多行 `data:`、跨事件增量和 `[DONE]` 结束标记。
- `delta.content` 与 `delta.reasoning_content` 分开累计。推理内容不写入最终 JSON，也不发送到聊天区。
- 设置三层保护：总 SSE 流量 16 MiB、推理内容 8 MiB、可见正文 4 MiB。触发时分别提示，避免推理内容挤占正文上限。
- 可通过 `max_tokens` 设置向兼容 API 透传输出上限，并限制在 131072 以内；未配置时保持原行为。
- 保留 `finish_reason`、`[DONE]`、连接中断、截断和格式异常诊断。

岗位/HR 关联、提示词预算、脱敏与数据存储边界没有改变。

## 验证与边界

- 传输专项测试 17 项通过：覆盖大量推理内容、推理单独超限、正文超限、多行 SSE、无推理字段旧供应商、截断、断连、格式错误、取消和回退。
- 需使用便携包内 Python 3.12 运行完整测试；系统 Python 3.9 缺少项目依赖，不能作为完整回归基线。
- 尚未调用真实 DeepSeek API 验证实际模型的 `reasoning_content` 字段和结构化 SSE 组合；需在工作台重新测试连接后再做一次深度岗位分析。
- 本版仍是 RC 测试版，不是正式 v1。
