# v0.10.6 · 配对与模型接入引导修复

修复 v0.10.5 首次引导隐藏配对入口、却提前要求回 BOSS 确认岗位的死循环。

## 使用顺序

1. 未连接侧栏点击“打开工作台，获取配对码”。
2. 工作台显示实际端口、生成/复制配对码。停留在工作台页面即可打开扩展侧栏，填写端口和配对码，点击连接；不要求已有岗位或简历。
3. 服务端确认配对成功后，工作台自动进入模型接入；已完成的配置继续保留。
4. 选择本机 Codex 或自己的 API。API 填地址、模型、密钥，高级兼容选项默认收起。保存并检查后才继续；失败留在当前步骤，可改配置重试。
5. 选角色与称呼，录入简历，核对本地脱敏预览。
6. 此时才提示回 BOSS，看第一个岗位并主动点击快速分析。

Codex 接入检查仅验证本机可执行文件存在，页面明确说明登录与额度在首次对话验证。API 连接测试仅发固定测试文字，不发送简历。

## 修复范围

- 配对状态来自服务进程的有效授权；生成配对码不等于连接成功。
- 重启/撤销/明确断开后恢复配对入口；新配对请求等待新的配对修订号，避免旧授权阻止扩展重载后的重新配对。
- 首次刷新时依据当前步骤定位页面，无需依赖特定 hash，配对成功后继续未完成步骤。
- 脱敏确认不再立即关闭工作台。返回前再次检查配对状态，资料保留。
- 补齐扩展后台 `/onboarding-complete` 允许路由，避免侧栏“结束引导”被后台拒绝。
- 检查响应 `ok=false` 必须停留当前步骤；提交期间阻止重复连接检查。

## 验证

80 项 Python 测试、48 项 JavaScript 测试通过。新增/扩展覆盖真实 HTTP 配对前后状态、无岗位生成配对码、断开重连、旧授权下重新配对、连接检查失败重试，以及扩展后台结束引导路由。

隔离临时数据库通过真实浏览器验证：生成配对码 → 模拟扩展 Origin 完成服务端配对 → 工作台自动进入模型设置 → Codex 本机检查 → 角色 → 虚构档案 → 脱敏 → 返回 BOSS 提示。没有使用真实 API 密钥或调用模型；未代用户重载 Edge 扩展完成实站全链路验收。

## 更新

工作台刷新后，侧栏需在 Edge 扩展管理页重新加载到 0.10.6，再刷新 BOSS。服务重启后从侧栏“打开工作台，获取配对码”重新连接。已保存模型配置、简历和历史不需要重新录入。
