# Edge 独立精确页修复 0.4.6

## 现象

从列表页点击“来源岗位”后，独立 `/job_detail/<id>.html` 页面仍提示“职位正文缺失或不唯一”，或停留在“详情标题与选中岗位正在同步”。用户诊断已经显示该链接就是当前岗位的独立精确页，不能再按列表页的标题同步规则处理。

## 修复

- 以独立页 URL 中的岗位 ID 作为身份依据，唯一 `h1` 作为标题来源。
- JD 候选统一从可见 `.job-sec-text,.job-detail-description,p.desc` 中选择。
- 排除 `.salary-info` 和 `.company-info-box`；优先选择 `.job-detail-section` 内正文。
- 兼容真实页面中 `.job-detail-section` 与 `.job-detail` 不是祖先关系的布局。
- 多个候选块仅在最长块明显（至少为第二块 1.5 倍）时采用，其他情况继续安全失败。
- 独立页成功后直接返回，不进入列表页的“选中岗位标题同步”校验。
- 诊断版本更新为 `0.4.6-diagnostic`。

## 验证

根据用户提供的真实诊断结构加入合成 fixture：705 字正文、41 字薪资块、345 字公司介绍块、唯一 `h1`、多个公司链接，验证只读取岗位正文。扩展测试 15 项全部通过，后端测试 19 项全部通过。

## Edge 更新步骤

1. 在 `edge://extensions` 找到“求职搭子”，点击“重新加载”。
2. 确认侧栏顶部版本显示 **0.4.6**。
3. 刷新 BOSS 列表页和已经打开的独立职位页。
4. 在列表页点击“来源岗位”，等待独立页面加载完成后点击“重新识别”（如侧栏没有自动更新）。
5. 若仍失败，请把新的 `0.4.6-diagnostic` JSON 发回；不要继续使用 0.4.5 目录。

本次代码和合成结构已验证，但在用户重新加载开发扩展前，不宣称真实 Edge E2E 已完成。
