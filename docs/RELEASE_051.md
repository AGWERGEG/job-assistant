# 0.5.1 同岗位浏览稳定性修复

用户反馈：BOSS 双栏列表中，左侧选中的岗位没有改变，仅在右侧浏览/展开岗位详情，侧栏却清空已读取岗位并要求重新确认。

## 原因与修复

原侧栏以完整 capture 的 JSON 作为身份；正文、标题或条件文本变化都会判为换岗。同时，每次稳定时间不足800ms的读取都被当作空岗位，立即清空确认与消息。

本版将岗位身份与正文快照分开：

- 用 job_key 判断岗位身份。独立页使用URL，双栏优先使用左侧选中卡片、右侧详情链接。
- 内容脚本分别记录身份与完整内容的稳定时间，避免无关正文变化导致反复从零等待。
- 同ID时已确认JD保持快照，不自动更新后端revision、不清空消息、不撤销确认。
- 正文暂时缺失但身份仍相同，可以基于原快照继续对话；身份也无法确认时保留全部已读状态，只暂停发送，恢复后自动继续。
- 选中卡片换到B但正文仍是A时，立即阻止向A发送；B正文稳定后再允许确认B。
- 只有岗位卡片中的点击参与切岗判断，右侧展开、相关推荐等点击不会冒充左侧选择动作。
- 离开页面路径、换标签页、换岗位ID仍撤销旧确认。主动“重新识别”可以刷新同一岗位快照，需重新确认。

## 验证

20项JS测试通过，包括同ID正文变化/稳定时间归零、正文暂时缺失、身份暂时未知后恢复、左卡B/右文A、发送前切岗拦截、右侧链接与左侧卡片点击区分。其余36项后端测试通过。

这些是模拟DOM/扩展消息回归。修复后真实Edge滚动操作尚需安装更新后验收，不宣称独立精确页提取问题已解决。

## 更新

只变更扩展代码，后端仍兼容0.5.0，不需要迁移用户数据或重新配置模型。把新版extension目录内容更新到Edge已加载的目录，重新加载扩展，再刷新BOSS标签页。侧栏显示0.5.1。若使用新的解压目录，确认Edge加载的是新目录。

验收：确认岗位A后上下滚动右侧、展开详情，确认状态和聊天记录应保留；点左侧岗位B时，侧栏应要求确认B，不应继续使用A。身份无法读取时，只暂停发送并保留记录。

正文适配诊断版本仍为0.4.6-diagnostic，侧栏发布版本为0.5.1；本次增加独立身份读取，不改正文选择规则。
