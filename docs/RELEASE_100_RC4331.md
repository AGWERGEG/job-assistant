# RC4.3.31 · 意图与多模型分工测试版

意图模型判断目前只覆盖兼容 API 对话 Agent。本机 Codex 聊天仍按原有按钮和明确句式分派。

兼容 API 普通聊天现在先用一个有总时限的模型请求判断**本轮用户**是否明确要求后台深入分析、岗位简历、HR 沟通或面试准备。判定必须给出本轮消息中的原文片段；引用、否定、假设、第三方转述和单独的“好/可以”不能成为建单依据。旧的明确句式保留为即时路径和模型漏判、不可用时的兜底；明确点击的专项按钮仍直接执行。创建任务时，数据库再次核对原消息身份、岗位、租约、隐私批准、资料版本、目标绑定及幂等键。模型不能用改写后的指令代替用户原话。已创建任务的状态按真实回执显示。

工作台设置页现在可保存多条相互独立的兼容 API 连接，按意图判断、日常聊天、深入分析、简历、面试和 HR 沟通分别指派连接与模型。未指派的任务沿用原单 API 或 Codex 设置；已指派但连接缺失或配置不完整会明确失败，不会静默换到另一服务。指派前需确认该连接会接收对应任务所需的脱敏职业信息。删除连接时清除引用它的指派。模型列表只从用户已保存的连接获取，失败时仍可手填；列表只提供模型 ID，不能证明它支持工具、JSON 或流式回复。

模型列表请求在受限子进程中执行，凭据经 stdin 传递；父进程掌控总时限并可终止，禁止重定向，限制响应大小和模型数量。密钥不会返回设置页、侧栏或测试包。聊天意图判断会增加一次模型请求，因此可能增加延迟和费用；选用低延迟模型并在实际接口观察耗时。意图层不会自动把聊天补充经历写入档案，仍按 RC4.3.29 的核对与再次脱敏批准流程。

离线回归覆盖合法续做请求、引用/否定/转述、失败回退、同轮幂等、多连接模型指派、模型列表超时和密钥不回显。真实 DeepSeek 与招聘站点 Edge 联动需要在本版实际安装后再验收。本版仍为 RC 测试版，不代表正式 v1 发布。
