# v1.0 RC4.3.5 智联公司在招岗位卡片读取修复

日期：2026-09-23。此版本是源码与扩展测试包，不是正式版或便携运行包；macOS 便携包仍为 RC4.3.2。

## 问题与改动

在智联公司 `/companydetail/jobs-<公司ID>/` 页面，真实页面显示两张在招岗位卡片，RC4.3.4 侧栏却显示“0 张已加载岗位卡片”。现场只检查公开岗位链接、标签和类名，确认卡片是 `.job-onlinelist .job-onlinelist__jobs__item`，岗位链接位于 `.job-onlinelist__jobs__info__href`，薪资和条件分别在同卡片的薪资、福利标签中。旧代码扫描到了链接，却没有在祖先选择器中识别该卡片，因而没有生成岗位材料。

RC4.3.5 增加该卡片结构及薪资、可见条件选择器。仍要求每张卡片只有一个可核对的智联岗位 ID，并位于公司主招聘列表内；“精选职位推荐”、异公司卡片、招聘者资料、投递按钮和分页数量不进入公司材料。仅保留当前页面已加载卡片，不自动翻页。卡片是岗位概况，不是完整 JD；若需完整同公司对照，应打开具体岗位详情并明确保存。

## 验证证据

- Python 完整回归 107 项、Node 完整回归 91 项通过，`node --check extension/extractor.js` 通过。新增虚构 DOM 用例覆盖两张同公司卡片、异公司推荐排除、URL 去追踪参数、薪资/条件读取及招聘者文字排除。
- 真实 macOS Edge 的智联公司招聘页可见 2 个在招职位。将修复后的提取脚本同步到已加载测试扩展并重载、刷新后，侧栏从 0 改为“2 张已加载岗位卡片”。现场固定目标是 BOSS 岗位，跨站保存按钮保持禁用；未切换目标或改动用户公司材料。
- 隔离临时数据通过窄 Bridge 保存智联同公司卡片及显式打开的另一岗位完整 JD，重复保存不增 revision，异公司来源被拒绝；新建岗位分析提示包含两类材料，目标岗位未被替换。此结果不等于真实用户工作台中的保存或模型回复验收。
- 新 ZIP 已在全新临时目录解压，使用隔离数据启动 `/api/health`，返回 `1.0.0-rc.4.3.5`；进程随后终止。现场已加载扩展与原服务的版本标识仍为 RC4.3.3，因此同版 Edge 扩展/服务完整联动、其他智联公司页面版式、真实保存→工作台核对→模型分析闭环与 58 登录后实站复测仍待完成。

## 测试安装

把 RC4.3.5 源码测试包解压到独立目录，按 README 启动其中的本机工作台，在 Edge 加载包内 `extension/` 并停用旧版本扩展，然后刷新智联页面、重新连接工作台。先确认目标为**同一智联公司**，再打开其“在招职位”页保存卡片材料；工作台应显示来源和已加载范围。测试包不包含 `data/`、`data-demo/`、SQLite、API 密钥或浏览器配置。
