# v0.8.1 后台聊天分离与简历本机回填

2026-09-17。本文件是V08_HANDOFF的增量修复说明。

## 用户可见变化

- 优化简历/深度分析放到后台通道；同一岗位仍可聊天、快速分析或生成HR招呼。两个通道各保留一项未完成请求限制，避免重复点击/无序对话。同一聊天通道的回复生成期间仍需等完成或取消后再发下一条。
- worker保留一个聊天执行槽，其他槽处理后台任务。启用worker时最少2、最多4；--workers 1会按2运行；默认仍为2。未引入队列框架，无新增模型调用。单次CLI worker-once仍是手动单任务。
- 后台任务按创建时快照执行；之后聊天不会静默修改运行中的简历。新增经历需取消重做，或完成后再迭代。
- 简历卡片按钮改为“保存这一版并导出 Word / PDF”，保存后直接打开本机回填预览。验收版本区默认展开，导出按钮不藏在每版正文折叠内。
- 下载前预览可编辑，必须勾选核对确认；编辑后确认重置。Word(.docx)、PDF、TXT均下载同一份核对正文。

## 本机回填与边界

- 从生成该版本时的原始profile快照读取，绝不把后来的另一份档案、JD或HR联系方式混入。
- 唯一姓名、手机号、邮箱自动回填；模型省略联系方式时补到简历开头。手机/邮箱可来自简历未标注字段的页头，存在多个候选则不猜。
- 地址、微信只在原稿有对应字段、原档案有唯一标注值时回填。身份证、密钥等不自动补回。
- 旧版通用[本地隐去]可能对应多个人名、学校或公司，无法安全逆推。未能匹配的占位符提示人工补齐，未处理前禁止下载；不能声称任意旧稿信息100%自动恢复。
- 回填预览与用户编辑只流经本机HTTP导出接口，不写入messages、tasks、resume_versions，不进入模型提示词，不发送给扩展。关闭预览清空临时文本；浏览器下载文件会包含真实个人信息，需用户自行保管。
- 旧GET /api/resume-export/<id>保留原验收文本导出兼容，界面已改用核对后POST下载。正式用户入口为预览确认路径。

## 工程改动

- store.task_lane、queued_tasks(lane)：两通道准入/重试及FIFO领取；保持请求ID幂等与租约。
- worker(lane)、server：聊天专用槽；无需数据库迁移。
- web与extension：分别判断chat/background待办，不用一个pending锁住全部按钮。
- resume_restore.py：本地预览及占位符校验；resume_export.py接受仅用于下载的已确认正文。
- POST /api/resume-export-preview {version_id} 与 /api/resume-download {version_id,content,confirmed,format}：本机token与来源校验，未向bridge开放。

## 验证

- 60项Python、28项扩展JS测试通过。新增并发测试让简历保持运行，验证聊天先完成；同通道仍防重复；重试、回填、旧快照隔离、原prompt不变、无标签联系方式和歧义不猜均覆盖。
- 独立8425虚构数据+本地模拟服务走通：点击优化简历 → 任务运行中成功发送聊天 → 两条结果完成 → 保存验收 → 自动回填姓名/手机/邮箱 → Word/PDF下载。此为工程流程验收，不是真实模型效果/速度评测，不消耗付费模型token。
- 导出接口返回实际DOCX和PDF；按文档/PDF技能渲染逐页检查，中文和回填联系方式可读，无遮挡或缺字。
- 本机8421在无排队/运行任务时备份后升级0.8.1，原用户档案及API配置保留。Edge侧栏改动通过合成测试，仍需用户重载0.8.1扩展并重新配对后实站确认。
