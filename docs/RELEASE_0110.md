# v0.11.0 · 侧栏与工作台联合 UI 改造

本版完成第一阶段侧栏和第二阶段工作台的使用结构改造。后端模型、资料保存、配对权限及导出协议不变，无新增依赖或数据迁移。

## 侧栏

- 顶部为搭子称呼、连接状态、工作台入口与更多功能。版本号移至连接与诊断。
- 已确认岗位压缩为一行，点击岗位条或“⋯”打开详情面板，可通过“收起”或 Esc 返回。
- 对话记录独立滚动；三个快捷动作和输入框常驻底部。常规状态说明压缩到底部一行；错误仍可展开阅读。
- 岗位原文来源、公司背景、面试/进展、休息、重新识别和诊断保留在详情面板。
- 浏览其他岗位时只出现小型切换提示，对话仍属于明确选定的原岗位。点击“切换到这个”才确认新目标。
- 切换岗位保留各岗位本次侧栏会话中的未发送草稿。关闭侧栏或刷新后未发送草稿不持久化。
- 阅读历史消息时，新结果不强制把滚动位置拉到底部；原本位于底部时继续跟随。
- 修复首次引导显示新候选岗位、却继续分析恢复旧目标的边界：引导按钮的明确点击会先确认眼前岗位。

## 工作台

- “继续聊”以聊天为首屏，不再被欢迎介绍、岗位重复说明和长任务列表挤压。
- 输入框与快捷动作位于聊天区底部；消息区独立滚动。
- “任务与成果”显示待办数量，点击打开任务面板。选择结果后关闭面板并定位正确岗位、页签与任务。
- 机会资料分为：分析、简历、面试、岗位与公司、记录。岗位/公司原文从分析页面移出。
- 任务结果默认展开最新一项，其他历史项收起；深链接会主动展开指定结果，编辑草稿切换页签保留。
- 简历页增加“为这个岗位优化简历”入口；保存验收、Word/PDF 导出仍使用原流程。
- 机会列表保留搜索与折叠；主要按钮与辅助入口统一间距和层级。

## 验证与边界

80 项 Python 后端测试、51 项前端/扩展测试通过。新增覆盖紧凑目标切换、分岗位草稿、首次引导新旧目标一致性、任务面板直达、资料页签与手动建岗。

真实浏览器使用隔离虚构资料验收工作台；侧栏使用同一份正式 HTML/CSS/JS 和模拟扩展消息进行布局验收，不调用招聘网站和付费模型：

- 380×720 侧栏：发送按钮底部约 682px，消息区约 407px，页面无外层长滚动。
- 320×560 侧栏：发送按钮底部约 525px，无水平溢出；详情打开/收起正常。
- 1280×720 工作台：发送按钮位于首屏，任务面板可打开并定位简历结果。
- 768×600 工作台：输入与发送保持可见，无水平溢出。
- 公司/岗位资料页签、任务定位与聊天返回已实际点击验收。

新版 Edge 扩展真实招聘网站链路仍需要用户重载后联合测试；上述模拟采集不代表所有 BOSS 布局已实站验收。独立 JD 页历史识别限制维持原状。

## 建议一轮测试

1. 重新加载 extension，确认“连接与诊断”版本为 0.11.0。刷新工作台/BOSS，服务重启后重新配对。
2. 看岗位 A 并确认：首屏有对话、三个快捷动作和输入框；岗位资料不占大卡片。
3. 看岗位 B：目标仍为 A，点击切换后才聊 B；再切回 A 检查未发送草稿。
4. “⋯”打开公司背景/读取帮助，收起后回到原对话，不丢草稿。
5. 提交简历任务后继续聊天，从工作台“任务与成果”进入该岗位简历页，核对、保存与导出。
6. 在分析/简历/面试/岗位与公司之间切换，检查任务和资料归属；折叠/展开不会改变已读或验收。
7. 检查首次配对、模型接入失败提示和重新连接仍能继续，未配对时不出现可操作岗位按钮。

本轮交付为可联合测试版；更深入的品牌插画、动效和视觉资产未纳入本次两阶段改造。
