# v1.0 RC4.3.1 · 侧栏发送按钮解锁修复

测试用户在 Windows Edge 中已经连接工作台并固定岗位，输入框可以填写文字，但发送按钮持续灰色。问题不在配对、岗位识别或模型服务，而是侧栏页面轮询和用户交互共用了同一个 `busy` 状态。

首次恢复岗位时，侧栏会依次读取工作台状态、恢复目标、读取历史和读取当前BOSS页面。Windows或招聘网页响应较慢时，这条后台链路长时间保持 `busy=true`，而发送按钮的启用条件包含 `!busy`，因此界面会出现“岗位已显示、文字可输入、发送键不可用”。刷新页面仍可能再次进入同样状态。

修复内容：

- 将后台页面轮询改为独立 `polling` 状态，不再占用用户操作锁 `busy`。
- 恢复岗位后立即写入 `ready/current/contextSafe` 并刷新按钮，再异步读取历史记录。
- 页面采集、历史加载或BOSS响应较慢时，已固定岗位的普通聊天仍可立即发送。
- 明确发送、切换岗位、保存公司材料等用户动作仍使用 `busy` 防止重复提交。

新增合成回归：让历史接口永久挂起，验证恢复目标岗位后发送按钮仍可用，并能创建一次 `/talk` 请求。RC4.3.1 必须同时替换本地程序和 Edge 扩展；仅重启后端不能更新侧栏中的按钮逻辑。
