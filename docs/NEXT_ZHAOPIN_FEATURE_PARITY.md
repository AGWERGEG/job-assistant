## 2. 已核实的能力差距

| 能力 | BOSS 当前实现 | 智联当前状态 / 所需动作 |
| --- | --- | --- |
| 岗位读取 | 岗位标题、公司、JD、身份校验 | 已有适配，用户确认可用；保留为回归基线 |
| 普通聊天、快速判断、深度分析、岗位简历、HR 回复、面试准备/复盘 | 共享任务和模型处理链路 | 岗位进入工作台后可复用；要验收输入快照和任务跳转，不另造一套 worker |
| 读取本人在线简历 | 明确点击 → 本地草稿 → 核对 → 加入编辑器 → 保存 → 脱敏确认 | 页面识别、按钮、schema、来源 URL 校验和文案均有 BOSS 限制，需要端到端补齐 |
| 公司身份 | 从 BOSS 公司链接建立岗位—公司关系 | 当前智联只提取公司显示名，未建立可供公司资料链路使用的公司标识 |
| 企业背景 | 公司介绍、产品/业务、当前已加载招聘卡片、同公司对照 JD | 公司页面识别与后端来源/身份校验仍只接受 BOSS |
| 材料进入分析 | 公司材料版本、来源、快照、脱敏和预算已有实现 | 复用这些边界，验证智联资料确实进入新任务且不改变旧任务快照 |
| 选中文字补 JD | 独立 BOSS 岗位链接 | `selection-jd` / `use-jd` 仍硬编码 BOSS URL；需在智联唯一身份可确认时支持 |
| 页面切换保护 | BOSS 选中卡片、详情、公司页与固定目标保护 | 智联已有采集身份，但左卡点击提示仍是 BOSS 专用；需核查智联异步切换是否可能短时沿用旧 JD |
| UI 与诊断 | 多处 BOSS 专用名称、提示与入口 | 按实际站点/能力显示；隐藏不支持入口；更新诊断的站点和适配版本 |

企业背景获取在此指用户打开的招聘页面中已经加载的内容，不扩展为全网调查、私有接口或自动爬取。

## 3. 先处理的真实缺陷：简历误去重

位置：`web/app.js` 的 `mergeEditorValue()`。

现有判定包括：两段文字均超过 40 字，只要长度差小于较长段的 15%，就当成重复。此条件没有比较内容。另一个“互相包含”条件还可能把包含新增成果的较长版本整体跳过。

本轮通过原函数做了虚构输入复现：

- 旧段落：`负责客户需求梳理与售后技术支持。` 重复 3 次，共 48 字。
- 新段落：`负责财务预算编制与年度成本分析。` 重复 3 次，共 48 字。
- 两者内容不同；合并结果却完全等于旧段落，新内容未保留。

这说明现有“重复或高度相似经历会自动跳过”的提示超过了算法实际能力，不能原样复用于智联。

建议处理：

1. 只对规范化后完全相同的条目自动去重，不能只用长度、包含关系决定丢弃。
2. 相似条目、补充成果、日期/公司/职位/数字冲突进入对照预览，由用户决定补充或保留；默认保留旧稿和可见的新信息，不能静默覆盖或丢失。
3. 页面能可靠分出工作/项目条目时保留条目边界；只有整段文本时采用保守追加和核对提示，不猜结构、不让模型替用户确认事实。
4. 在已有“先核对、再加入编辑器、最后手动保存”流程内改进；导入本身不调用模型，保存变更后继续使旧脱敏确认失效。
5. 覆盖 BOSS → 智联、智联 → BOSS、文件简历 → 智联三种重复/增量导入，不仅测试单站重复点击。

## 4. 实施顺序与完成条件

### 第 0 步：真实 Edge 页面勘察

先用用户已登录 Edge 检查：本人简历页、已确认岗位里的公司链接、公司介绍页、公司招聘页、另一个同公司岗位。每次操作前获取当前界面状态，不能复用旧控件索引。

记录可脱敏的页面结构：站点/路径模式、栏目标题、节点结构、条目边界、分页或折叠状态、公司和岗位链接关系。简历正文、账号、Cookie、令牌和 URL 参数不得写入 fixture 或诊断日志；夹具使用虚构资料。

尚待实测，不能提前猜定的事项：

- 智联本人简历的真实域名/路径、编辑/预览页区别、多份简历切换、延迟加载方式。
- 简历栏目与现有七个字段的映射；没有读到的栏目应为 unavailable，不能当作 empty。
- 智联公司链接形式及不同页面 ID 是否确有同一实体关系。历史现场见过同名公司在不同位置出现不同 ID；不得靠名称相同、剥掉前缀或截断数字强行合并。
- 代招页的发布公司与“客户公司/实际用人单位”区别。发布公司资料不能呈现为实际雇主已确认背景。
- 公司介绍、业务、招聘列表哪些实际存在；不存在的产品栏目直接说明未提供。

完成条件：获得当前真实页面证据和虚构结构夹具，再确定选择器、URL 白名单和 schema 映射。页面登录/风控阻塞时明确记录，不能把猜测选择器标成已适配。

### 第 1 步：站点身份与能力边界

- 建立轻量站点适配接口，职责限定为页面类型、岗位身份、公司身份、岗位/简历/公司采集及诊断；复用 BOSS 的成熟路径，避免一次性重写整套 extractor。
- 简历页判断由统一站点能力返回，侧栏、采集器和后端校验必须一致。后端始终独立校验来源，不信任扩展自报的 source_site。
- 公司内部身份区分站点；推荐保留现有 BOSS 裸 key，给新增智联公司使用明确的站点前缀或独立来源字段。避免仅为统一格式而重写全部历史 BOSS 记录。
- 如新增数据库列或索引，提供幂等迁移，用临时的旧结构样例库验证；不打开、删除或迁移真实 data/data-demo 作为调试手段。
- 对现存智联岗位（没有 company_key）提供明确“补充公司关联”的动作，在当前相同岗位身份、scope/seq 均有效时建立关系。绑定已有目标不能悄悄重新采集覆盖已保存 JD；公司身份冲突须阻止保存。

完成条件：前后端对同一 URL 的身份判断一致；跨站同 ID、同名异公司、冲突链接和过期页面请求都不能串资料，旧 BOSS 目标仍可恢复。

### 第 2 步：简历导入闭环（先完成再扩展其他分支）

- 先修复第 3 节的误去重，再增加智联适配。
- 明确点击“读取智联在线简历”才读取本人当前选中的简历；轮询快照和诊断绝不包含简历正文，也不批量读取多份简历。
- 引入可区分来源的简历协议。旧 `job-assistant.boss-resume.v1` 与已有草稿保持可读取；新来源保存准确的 source、规范化来源、状态和时间。新协议名称由实施时确定，不能只放宽 BOSS schema 的主机校验。
- 复用 `/bridge/resume-import` → 本地草稿 → `/api/profile-import-draft` → 工作台核对，扩展仅获得草稿引用，不获得档案读取权限。
- 空栏目、未读取、掩码字段分开显示；不恢复掩码信息，不读附件、诊断、隐私设置或平台推荐。
- 工作台显示实际来源，支持查看新增/重复/待核对项；加入编辑器后仍由用户保存并重新确认脱敏。

完成条件：重复导入幂等；真正新增经历不丢失；旧经历不覆盖；不触发模型；BOSS 导入回归通过；真实智联一条导入—核对—保存—脱敏路径通过。

### 第 3 步：企业资料与同公司对照闭环

- 智联岗位采集增加有来源依据的公司标识与公司链接；可靠身份缺失时仍可使用岗位分析，但公司保存明确说明阻塞原因。
- 先实现当前岗位里的公司介绍及公司详情页介绍保存，再支持实际存在的业务/产品栏目、当前已加载招聘卡片、同公司岗位对照 JD。
- 扩展 `company_ref()`、`source_url()`、`Company.ingest()` 等后端验证，限制真实观测过的站点与页面类型。不能简单允许整个智联域名所有 URL。
- 只保存与固定目标公司关联的材料；推荐公司和推荐岗位不能混入。同公司对照不能替换固定聊天目标；跨站公司不能仅凭同名自动合并。
- 代招场景清楚标注发布主体与未知的实际用人主体，未取得证据时不合并成同一家公司。
- 保留来源、企业自述标签、读取时间、partial、当前已加载范围；招聘数字与卡片数量不是完整 JD 采集数量。
- 复用材料内容去重、公司 revision、旧版本证据、任务快照和脱敏预算。重复保存不增版本；新增材料进入下一次任务，旧任务快照不回写。

完成条件：岗位确认 → 公司资料保存 → 同公司对照 → 工作台查看来源 → 新建分析使用这些资料；异公司、代招误绑定及来源冲突必须拒绝或明确待核对。

### 第 4 步：整体功能对齐与发布验收

- 补齐智联选中 JD 兜底；仅在当前唯一岗位身份有证据时允许，不从列表页猜 ID，不构造 BOSS 来源 URL。
- 核查智联快速切换卡片、旧响应迟到、公司页往返、关闭重开侧栏、同步已保存岗位等场景。
- 清理 BOSS 专用引导和名称，按站点/能力显示简历、公司入口；保留 BOSS 特有能力的真实说明。
- 验收工作台标签复用、任务深链接、详细分析后台路由、历史查看、取消与重试、岗位简历导出和本机回填。
- 模型处理层原则上复用。仅在任务输入/输出证据证明需要修改时调整；改 worker 或上下文前读 `docs/RESUME_RESEARCH.md`。
- 最后更新版本/能力标识、交接、验收记录和测试包。扩展与后端共同升级并验证，不沿用同一个版本号掩盖能力差异；仍标 RC，Windows/58 不得随智联结果宣称通过。

## 6. 验收门槛

1. 简历：不同内容同长度不丢失；同经历多一条成果可核对补充；相同内容重复读取不堆叠；缺失栏目不清空旧数据；来源伪造/不匹配 schema 被拒绝。
2. 企业：同名异 ID 不自动合并；不同站点同 ID 不相撞；目标和公司页身份一致；推荐、代招与真实雇主不混淆；重复资料不增版本；更新材料使旧结果标记过期。
3. 状态：切岗位瞬间点击不会把旧 JD 提交为新岗位；公司页仍固定原目标；现有智联岗位补公司关系不覆盖已保存 JD；重开后目标恢复正确。
4. 隐私：未明确点击不能读取简历；诊断不含正文/凭据；导入不调用模型；资料变更后重新脱敏；公司材料进入任务前仍脱敏并遵守预算。
5. 回归：BOSS 简历/公司、现有智联岗位和 58 既有适配不回退；必跑 RC transport/release、company 及相关前端用例，最终完整回归。
6. 真实 Edge：分别记录简历闭环和公司闭环证据，区分自动测试、人工页面确认、真实模型调用。Codex 接入继续按用户要求暂不核查；外部模型测试单独说明实际结果。

## 8. 2026-09-23 实施进度

代码已加入源码测试包，但没有完成真实验收；源码包只包含开发中的智联兼容调整，不代表完整功能交付：

- `web/app.js` 的经历合并已改为仅对规范化后完全相同的内容自动去重；相似但不同的经历保留待核对。虚构同长度经历回归覆盖通过。
- `extension/extractor.js` 和 `app/company.py` 初步增加智联公司身份、公司介绍/业务标题采集及窄来源 URL 校验；不采集推荐内容，不按公司名称合并。
- 对没有公司键的已确认岗位，侧栏现可通过明确按钮调用 `company-bind`，后端验证 scope、序号、站点、公司页面身份并拒绝替换已有绑定；随后复用原公司材料保存链路。
- 智联独立 `/jobdetail/<id>.htm[l]` 增加显式选中文字补 JD 的身份核对和无追踪参数来源 URL。列表页不允许使用该兜底。
