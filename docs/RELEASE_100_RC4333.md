# RC4.3.33 · 专项结果引用与意图路由修复测试版

本版针对 RC4.3.32 实测发现的三类问题：引用已有“深入分析”结果时，消息中的“深入分析”会被误当成新建任务；模型已判断为聊天时，旧规则仍可能二次建单；多个同类结果在界面上没有足够标识，选择结果后也看不出实际引用了哪一条。

## 修复内容

- 增加“讨论已有结果”边界。引用模式保留结构化 `reference_task_id`，问题正文不再偷偷拼接“围绕结果”；已选结果时禁止创建同类新报告。
- LLM 返回 `chat` 后不再继续走旧建单规则。旧规则只在意图模型超时、无效格式或不可用时兜底。
- 对“HR 没深聊几句就说可以来面试看看，请深入分析分析，这个岗位是否真的合适，感觉岗位留不下人”这类具体讨论问题，模型和本地守卫均按聊天处理；“请深入分析这个岗位”仍保留独立建单路径。
- 工作台与侧栏 `/` 菜单分为“创建新的专项任务”和“引用已有专项成果”两组。引用项显示类型、完成时间、短任务 ID 和摘要；选择后在输入框下显示“已选结果”标签，可移除引用。输入 `/深入分析` 会清除旧引用并创建新任务请求。
- 侧栏展开卡片现在实际挂载结果正文；点击“围绕此结果继续聊”只设置结构化引用。

## 验收证据

- Python 完整回归：196 项通过。
- Node 工作台与扩展回归：107 项通过（使用临时 `jsdom@26` 依赖）。
- 真实 DeepSeek `deepseek-v4-pro`：截图二的复杂问句返回 `chat`；两条虚构分析结果中明确选择第二条后，回复包含第二条唯一标记、不包含第一条标记，后台分析任务数量保持不变。
- 临时 SQLite 与虚构资料验证：引用结果的任务 ID 精确写入快照；已选引用不会创建新分析任务；模型 `chat` 决定覆盖旧规则；`/` 菜单的行动命令和结果引用可区分。

## 限制

本版仍是 v1 RC 测试版，不是正式 v1。没有操作用户当前 Edge 会话，也没有在真实招聘网站页面重放完整 BOSS 流程；Node 测试是隔离 DOM 验证，不能替代招聘网站现场验收。真实 DeepSeek 测试使用虚构岗位、经历和临时数据库，密钥只通过标准输入传给测试进程，不进入源码、日志或包。
