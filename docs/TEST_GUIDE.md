# 求职搭子 v0.2 直接测试指南

## 测试前

需要 Python 3.10+ 与已登录的 Codex CLI。运行 `python3 job_assistant.py doctor` 确认 `python_ok` 和 `codex_auth.ok` 为 true。

自动分析会把当前任务快照中的画像、岗位 JD 和 HR 对话发送给用户已经登录的 Codex 服务处理，并消耗其额度。SQLite 与上传文件保存在本机。若不希望自动调用，使用 `python3 launch.py --no-worker`。

## 启动

- macOS：双击 `启动求职搭子.command`，或运行 `python3 launch.py`。
- Windows：双击 `启动求职搭子.bat`，或运行 `py -3 launch.py`。
- 页面没有自动打开时访问 http://127.0.0.1:8421 。关闭终端窗口或 Ctrl+C 即停止服务。

如果 8421 已占用，运行 `python3 launch.py --port 8422`。

## 十分钟测试

1. 上传 TXT、Markdown、DOCX 或普通文本 PDF。扫描件暂不支持 OCR。
2. 检查“已确认的真实经历”。删除不准确内容，补充目标方向和明确限制，保存画像。
3. 从 BOSS 或其他网页复制一个职位名称和完整 JD。用户自行登录招聘网站；本版不读取登录态，也不发消息。
4. 保存岗位，点击“判断岗位”。结果应给明确投入建议、岗位真实重心和下一步，不应只有匹配项清单。
5. 点击“定向改简历”。检查它是否继承岗位判断的主打方向，重新安排重点并给可直接使用的岗位版本；不应杜撰数字或改变学历、年限和职责。
6. 把一条脱敏 HR 消息放入“HR 消息或沟通需求”，保存后点击“准备回复”。检查薪资、到岗、出差等承诺是否要求本人确认。
7. 如果结果出现补充问题，点击“回答并再次生成”，补上真实信息后重新点同一功能。新版应吸收回答、减少问题，并沿用当前岗位策略。
8. 修改画像后查看旧结果，应提示基于旧版本；再创建新任务进行比较。

结果是草稿。点击复制或下载 Markdown 后，仍由用户自行修改、发送和投递。

## 故障处理

- 页面显示“分析失败”：展开错误，先运行 `python3 job_assistant.py doctor`。确认登录和额度后点“重试”。
- 一直显示处理中：单任务最多等待约 4 分钟；之后会失败并允许重试。
- PDF 无文字：上传未加密、可选择文本的 PDF，或粘贴正文。安装 `requirements.txt` 可提供 pypdf。
- 页面打不开：确认启动窗口仍在；换端口启动；不要把服务暴露到公网。
- 不想自动调用 Codex：停止后以 `python3 launch.py --no-worker` 启动。

每个测试岗位建议记录岗位类型、任务耗时、建议是否采用、事实错误、遗漏条件和是否愿意再次使用。不要把匹配判断当成面试成功率。
