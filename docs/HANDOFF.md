# 交给下一位模型

> 当前版本为 **0.5.0 陪伴闭环内测版**。先读 [v0.5 使用与工程交接](V05_HANDOFF.md)。下方0.4及更早说明为历史记录；界面、脱敏、接入与验收范围以v0.5为准。

v0.4 更新：先读 [V04_HANDOFF.md](V04_HANDOFF.md) 与 [BROWSER_SIDEBAR.md](BROWSER_SIDEBAR.md)。新增浏览器侧栏、配对、DOM 采集、缓存与防串岗；真实 Chrome/Edge 与 BOSS 页面仍待验收。以下是之前的核心能力说明，冲突时以 v0.4 增量为准。

## 当前目标

把这个框架推进到可内测的桌面 Codex 求职辅助 MVP。用户在主聊天提问，在侧窗浏览 BOSS，在本地工作台上传简历、核对经历并查看建议。第一版不发送或投递。后期自动筛选/投递只是路线图。

## 先读与启动

读取根目录 AGENTS.md → 本文 → MVP_ENGINEERING.md → 相关实现。启动 `python3 launch.py`，打开 http://127.0.0.1:8421。Python 3.10+，核心无第三方依赖；PDF 可选 pypdf。不要假设别处模型也有本会话的浏览器或语音工具。

## 已完成

- 原生 Web 工作台，可编辑画像、岗位和聊天摘录。
- TXT/MD/DOCX/PDF 可选解析与文件保存；上传后用户核对并保存事实。
- SQLite 持久化，三类任务，创建时快照、重复点击去重、单执行者领取、15 分钟租约和结果回写。
- 页面自动刷新，结果版本过期提示，Markdown 导出。
- 项目 Skill、CLI、虚构样例、基本测试和工程文档。
- v0.2 增加本机 Codex CLI 自动 worker、一键启动、doctor、失败/重试/取消。worker 使用独立临时会话，不是当前主聊天。
- v0.3 重构专业工作流：岗位判断产生共享策略，简历和沟通继承同一定位；输出区分明确决策、直接可用内容、最多两个高价值问题和详细依据。详见 `docs/RESUME_RESEARCH.md`。

## 还没有

- 没有 MCP server 或当前聊天自动唤醒；自动 worker 需要目标机器已登录 Codex CLI，并消耗用户额度。
- 没有真实 BOSS 读取实现或登录验收；Skill 描述的读取依赖宿主。
- 没有 OCR、PDF/DOCX 输出、删除 UI、结构化事实引用校验。
- 没有语音、桌面安装包、多人账户、招聘网站写操作。

## 建议接着做

v0.3 已用脱敏的 AI 产品销售样本完成三类策略继承和追问迭代。下一步先用宿主实际浏览器读一个用户指定的真实 JD，通过 job-save 创建岗位，再由真实用户评审岗位判断、定向简历和回复是否有用，记录采纳与纠正。完成真实用户评测前不要扩展 SDK、实时语音、多模型或自动投递。

下一步再实现事实 ID/来源、捕获时间、运行中取消与更清楚的错误分类、资料删除和中文简历固定模板导出。修改数据结构需迁移已有 data，不要删除用户库。

## 可以复制给另一模型的提示

> 请继续开发当前 job-assistant v0.2 工程。先读取 AGENTS.md、docs/HANDOFF.md、docs/MVP_ENGINEERING.md、docs/VALIDATION.md 和 docs/TEST_GUIDE.md，并运行现有测试。目标是岗位分析、简历优化和 HR 对话建议。项目已有独立 Codex CLI worker，但没有当前聊天自动唤醒或 BOSS 浏览器捕获。先完成宿主浏览器读取用户指定 JD、事实 ID 与来源、资料删除及真实样本评测，再补其余 P0。不要把 demo 结果当 AI 验收。保持本地用户数据，不要把 data/data-demo 打进交付包。

## 本机现场

交付时工作台使用虚构 demo 数据目录，端口和启动路径见同目录 VALIDATION.md。真实简历不得放到 examples 或交付压缩包。源码所在父目录可能不是 Git 仓库；只有在实际运行 git status 成功时才报告 Git 结果。没有创建远程仓库或执行部署。
