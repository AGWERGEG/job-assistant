# v0.8.0 求职搭子交接与测试说明

2026-09-17。此文件优先于V06及更早说明。此次实现0.6.1状态恢复、0.7响应与进展、0.8简历交付；不扩自动投递、语音、多租户或新招聘平台。

## 已实现

### 连续使用

- 已确认目标按配对扩展Origin存后端saved_targets，不把简历/JD存进浏览器localStorage。重开侧栏时通过新的scope+seq恢复目标和历史，再核对当前页面决定是否可发送。
- 后端重启后需重新配对，配对后可恢复同一扩展的目标。更换扩展ID不会继承其他ID的目标；撤销连接清除保存目标。
- 工作台只在localStorage保存最后选中岗位ID。后端权威数据不存在则不恢复。
- 不同岗位浏览仍不替换明确固定目标；发送前继续核对同岗位或同公司证据。
- 网络失败显示恢复说明，重新连接不会把空白页覆盖原对话。

### 回复与任务

- 兼容Chat Completions API短对话/快捷分析采用SSE stream；专业简历、深度分析、HR招呼仍按完整JSON返回，避免把未完整JSON当答案显示。
- 不增加前端SSE连接层：worker按片段保存partial_text，工作台1秒、侧栏1.5秒轮询显示。为防手机号/姓名分片泄露，只发布已结束句子，完整累计文本经过脱敏后才写进数据库。
- 记录排队、首次文本片段、整个模型调用和总耗时。first_response_seconds指API首个文本片段到达，并非首句实际显示时刻。非流式调用不伪造首字数据。
- 支持运行中取消。DB立刻标记cancelled，旧结果/片段不可写回。Codex子进程轮询取消并终止；API等待期间会在下一条数据或超时退出，取消不能保证供应商立即停止计费。
- runtime.py只维护进程内执行中任务集合，防止任务取消但网络尚未退出时删除数据。删除界面提示稍候。
- API服务不支持stream时可取消“短对话逐段显示”；如果服务忽略stream并返回JSON也支持。断流无结束标志的回复标为失败，不能冒充完整结果。

### 求职进展

- career_events记录用户确认的已投递、已发招呼、面试邀请、面试完成、offer、入职，可撤销误记。
- 统计投递次数、公司数、招呼次数、验收版本数及首末记录跨度。生成/复制不会自动创建发送或投递事件。
- 公司去重优先BOSS公司ID，未关联时按公司名称；此时统计只是用户记录口径，不是法律主体核验。

### 档案与简历

- profile_facts为分类事实：教育、工作、实习、项目、校园、技能、补充。用户可从聊天纠正中手动填写并确认，记录来源；增删事实递增画像revision，必须重新核对脱敏预览。
- 新任务带已确认事实及ID，要求专业分析引用来源、纠正优先但不拼接夸大经历。旧原文档案保留，未做自动事实抽取/机器真实性验证。
- 同岗位两个验收版本以difflib统一文本差异比较；不同岗位禁止对比。
- 已验收简历可导出PDF、DOCX、TXT。固定单栏中文模板，Letter纸，11pt正文，不追求还原原PDF。模型输出的【小标题】和Markdown标题均可识别。
- Word使用python-docx，PDF使用ReportLab，加入requirements.txt；没有自动安装依赖。macOS PDF嵌入STHeiti Light，Windows尝试微软雅黑/宋体，Linux尝试文泉驿。没有可用中文TTF时明确提示JOB_ASSISTANT_CJK_FONT，不输出空白PDF。不附带系统字体文件。
- 本地资料JSON导出不含API密钥、桥接token。此副本用于查看与迁移参考，尚无一键导入恢复。
- 明确输入“删除本机全部求职资料”后，删除当前数据目录内画像、事实、原件、任务、对话、验收稿、进展、公司资料、API设置、应用SQLite备份和drafts直属文件；不递归删除未知目录，不跟随符号链接。活动任务/网络退出前阻止删除。删除后撤销扩展配对。
- SQLite secure_delete+checkpoint+VACUUM降低当前数据库残留，不承诺SSD或系统备份安全擦除。手动导出到应用之外的文件不在删除范围。

## 架构与依赖

继续使用原Python标准库HTTP、SQLite、原生JS。新增app/journey.py、app/runtime.py、app/resume_export.py；schema8幂等新增3表和partial_text，不清旧库。不引入向量库、框架或任务中间件。

GitHub参考：
- https://github.com/python-openxml/python-docx ：使用其公开创建段落、样式与保存文档能力作为依赖，无复制其实现。
- https://github.com/openai/openai-python/blob/main/src/openai/_streaming.py ：参考SSE帧边界与结束语义，实际项目用标准库实现约定的Chat Completions流式子集；未引入完整SDK。
- OpenAI官方流式文档访问本轮被403/Cloudflare限制，未据此声称所有厂商兼容。通过本地SSE接口及用户已配置服务真实调用验证协议。

## 验证结果

- Python54项、JS27项回归通过，涵盖旧采集链路、恢复与撤销、流式片段/断流、分片敏感词、取消拒绝迟到结果、公司证据、事实审核、进展口径、版本对比、导出和资料删除。扩展取消/重试响应特别检查不回传原始任务快照或claim_token。
- 工作台真实浏览器在隔离虚构数据中走通：岗位分析 → 简历任务 → 保存验收版 → HR招呼；记录投递后统计变为1，生成招呼未计为已发送。
- 真实API测试仅3次，使用用户当前已配置服务、虚构简历与岗位，无用户真实履历进入测试，凭据不写报告。模型gpt-5.6-sol：快捷分析15.444秒（首文本12.019秒），简历21.769秒，HR招呼14.586秒。三项均完成并继承同一经历定位，未新增业绩数字。
- 快捷测试补充指令同时提到简历，输出有少量简历内容；随后收紧快捷模式不生成简历正文，未为此追加模型调用。不是固定延迟/质量承诺。
- 当前Codex额度只读检查显示5小时窗口已用100%，未反复消耗额度测试Codex。Codex适配取消/权限由模拟进程和既有回归覆盖，本轮真实模型验收来自API。
- DOCX与PDF使用虚构简历渲染逐页检查。发现并修复中文缺字、PDF字体未嵌入、Word模板残留装饰；最终中文可读无溢出。DOCX渲染器需在QA环境显式配置系统中文字体；该环境配置不进入发布包。

## 接口增量

- POST /bridge/restore：Origin配对后，scope+seq，恢复该Origin最后目标；不向扩展回传原始个人档案。
- POST /bridge/cancel、/bridge/retry：只允许当前目标messages中的任务。
- GET /api/journey；POST /api/journey-event、/api/journey-remove。
- POST /api/fact、/api/fact-remove：确认事实/修改revision。
- POST /api/resume-compare：a、b验收版本ID；GET /api/resume-export/<id>.pdf|docx|txt。
- GET /api/data-export；POST /api/data-delete：输入明确确认语句，活动任务保护。

## 已知边界与下一步

- 侧栏新版恢复/取消经过合成测试；本轮未替用户安装新Edge扩展完成实站验收，原BOSS复杂布局仍需持续收集问题。
- 出站脱敏为规则+用户确认，并非匿名保证；随意口述的第三方人名/地址仍可能遗漏。
- 进展无历史日期补录界面；跨度按实际录入时间统计。面试卡、复盘、祝福彩蛋、成功总结和作者寄语留到0.9。
- PDF只覆盖标准中文/英文文本，复杂emoji、其他语言、复杂Markdown表格不是模板支持目标。
- 无批量模型评测、长期性能统计、Windows真机安装验收和全量恢复导入。运行中API取消在无数据时受网络超时限制。
- 下一轮优先用户测试：重开侧栏恢复 → API逐段聊天 → 验收简历导出 → 手动确认进展。不要继续扩架构。

## 启动与升级

Python3.10+。缺导出依赖时安装requirements.txt。停止旧服务并备份实际数据目录后，用新版launch.py --data-dir 原数据目录启动。扩展和后端版本均0.8.0；Edge重载新版extension并刷新BOSS，服务重启需重新配对。

本仓库data-demo包含真实用户资料，不删除、不归档、不复制进ZIP。测试脚本qa_v08_server.py只在独立临时目录启动8424的模拟服务；smoke_v08.py仅显式执行时进行最多3次真实调用，不自动在启动运行。
