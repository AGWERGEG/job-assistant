# RC4.3.30 · 对话经历意图提示测试版

本版建立在 RC4.3.29 的“聊天经历核对入档”之上。此前每条已结束的聊天都有相同的“记入经历”入口；现在，兼容 API 对话 Agent 可将本轮用户直接陈述的已发生经历标为候选，并把入口显示为“可能是新经历 · 核对”。未标记的聊天仍保留手动入口。

这是一条模型辅助提示，不是独立的后台事实抽取或自动入库。模型调用工具时必须提供本轮用户原话中的片段，程序检查片段长度、第一人称及常见假设、计划、否定等表达。即使标记成功，数据库仍只保存候选布尔值；用户要自行核对编辑原话、确认保存，并重新批准脱敏预览，经历才会作为长期事实供后续新任务使用。候选判断可能漏报或误报，不能将其当作事实认证。纯手动或 Codex 对话模式仍使用手动“记入经历”入口。

当前任务意图判断分为两层。普通兼容 API 聊天由对话 Agent 决定是否请求资料工具或申请创建分析任务；明确的“深入分析”按钮及部分直接请求可由程序直接路由。创建后台分析任务还要通过基于**本轮用户原话**的保守授权规则，并由数据库在任务创建时再次核对，模型的判断或历史建议不能单独授权建单。引用、否定、第三方要求和模糊“好/可以”仍不能触发创建。

调用候选经历工具可能增加一次模型往返，因此需要在真实接入环境中观察响应耗时。自动化回归使用虚构文字和合成模型调用，验证候选提示、手动回退与未确认前不入档；真实 DeepSeek 识别率、耗时及 Edge 页面联动尚待同版环境验收。本版仍为 RC 测试版，不代表正式 v1 发布。
