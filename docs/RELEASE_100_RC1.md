# v1.0 RC1 · 发布前修复

本版为候选验收版，显示版本 1.0.0-rc.1。扩展 manifest 使用四段数字 1.0.0.1，version_name 明确标注 RC。不是正式 v1。

## 五项修复

1. 回退到已审核简历、原样保存后，页面由引导状态决定，不再强制切回档案造成空白。浏览器实测保存后和刷新后均进入浏览步骤。
2. 侧栏恢复已确认目标后继续采集候选快照；首次分析不无条件重新确认空候选。
3. 首次快捷分析在确认岗位前保存输入文字；失败保留草稿，成功才清空。
4. 工作台无变化保存岗位不增加版本；真实修改导致侧栏冲突时，提供“同步已保存岗位”。新 /bridge/sync 仅针对配对、scope/seq 校验后的已确认目标，读取本地修改，不拿旧网页覆盖它。
5. API 网络请求使用短生命周期子进程。父进程监控从启动起的总时限和取消信号；响应头等待、正文等待、SSE 等待、缓慢滴流都可终止。等待退出后释放 worker 通道，拒绝迟到回写。远端停止/计费行为不作保证。

## 发布与安装

- README 已替换为唯一当前安装/使用/升级入口，历史文档留在 docs，不作为当前用户指南。
- Windows 普通与演示启动器优先 .venv；启动提示实际解释器及缺失 PDF/Word 依赖。
- 包含本地主题，无联网字体或安装时自动配置密钥。
- 升级需保留并显式指向旧 data 或 data-demo；不要覆盖个人目录。
- 本轮不删除原数据、不运行原库任务作为测试、不改变账号与凭据。

## 验证

- Python：89 项；JavaScript：57 项。
- API 取消测试：响应头/正文/流式等待均能在测试阈值 1.5 秒内停止；滴流不能拖长 .35 秒总时限；下一请求可完成。
- HTTP 全链路测试：空库→配对→模型连接→角色/档案/脱敏→首次分析→简历后台任务→本机回填 DOCX/PDF→本地岗位同步→服务重启→重新配对恢复原目标及验收版本。
- 全链路模型为本机固定响应，未调用付费接口，不将其称为真实 LLM 质量验收。
- 浏览器使用隔离虚构档案验证回退原样保存后界面不空白。
- 发布 ZIP 使用白名单，排除 data/data-demo、SQLite、auth.json、缓存与依赖目录；解压后运行同一测试集合。

## RC 人工验收建议

1. Edge 重载扩展、刷新工作台与 BOSS，重新配对。
2. 已确认目标关闭重开侧栏，点首次分析或普通分析，验证可以继续。
3. 输入补充要求后首次点击分析，确认消息中保留这段文字。
4. 工作台原样保存岗位后侧栏继续聊；真实修改后点击“同步已保存岗位”，确认修改未被覆盖。
5. 回退到已审核简历并原样保存，确认继续进入下一步；可随时跳过。
6. API 发起任务后取消，再发下一任务，检查不被旧请求占住。
7. 保存验收简历并核对 Word/PDF 中回填信息。

## 正式版前仍需用户验收

本机真实 Codex/API 账号、真实 Edge 招聘页面、新机器安装、Windows 原生启动及中文 PDF 字体，需要在对应环境确认。独立 BOSS 详情页仍有布局识别限制；扫描 PDF 不支持 OCR；规则脱敏仍需人工核对。已清楚标在 README，未宣传全部环境覆盖。
