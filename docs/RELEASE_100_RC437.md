# v1.0 RC4.3.7 启动与同版连接修复

日期：2026-09-24。仍为测试版；岗位与 HR 绑定的真实 BOSS Edge 联动尚未验收。

## 用户遇到的故障

RC4.3.6 解压目录 `job-assistant 7` 的 macOS 启动脚本报 `无法启动本地端口 8421：[Errno 48] Address already in use`。只读检查发现旧 RC4.3.5 服务正在监听 127.0.0.1:8421。解压脚本与交付 ZIP 一致，失败由默认端口冲突引起。

## 修复

- 双击默认启动时，依次尝试 8421—8430；只对端口已占用这一种错误继续尝试，终端和浏览器使用实际端口。显式 `--port` 仍严格使用用户指定端口。
- 扩展扫描同一端口范围，优先选扩展版本对应的工作台，避免新版侧栏连到 8421 上的旧服务。
- 同一安装和数据目录再次启动时提示已有服务地址，不创建第二实例。若端口上的另一版本使用同一数据目录，拒绝并发启动并提示先停止旧服务。
- 旧进程和用户资料保持原状；新解压目录默认使用自己的空数据目录。需要继续旧资料时先停止旧进程，再用 `--data-dir` 明确指定原目录。

## 验证边界

完整回归通过：Python 120 项、Node 104 项。隔离数据的启动回归确认：旧 RC4.3.5 仍在 8421 时，新源码在后续空闲端口启动并报告 RC4.3.7；同一目录再次启动只报告已有实例，旧服务健康状态不变。扩展合成测试覆盖旧版在 8421、新版在其他端口时的同版优先发现。macOS Apple 芯片便携 ZIP 在全新临时目录解压，包内 Python 成功启动，`/api/health` 返回 `1.0.0-rc.4.3.7`，初始档案未就绪；随后进程终止并清理测试目录。真实 Edge 与 BOSS 绑定流程仍需用户方便时验证。

## 使用

完整解压 RC4.3.7 测试包后双击“启动求职搭子.command”，留意终端打印的实际地址。Edge 加载同包内 `extension/`；若侧栏曾连接旧版，可在高级连接区断开后重新连接终端显示的端口。不要为了排查反复刷新当前招聘聊天页面。资料不随 ZIP 附带。
