# v1.0 RC2 · 模型等待与流式兼容修复

Windows 非技术用户测试出现“连接测试成功，但聊天长期停在我正在整理这次回复”。附件的岗位读取诊断为 ready，因此问题不在 BOSS DOM。

现场核对显示真实 API 快速分析最终成功：首段约 68.6 秒，完整结果约 70.4 秒。原 UI 没有动态等待时间，用户会误认为无返回。连接测试此前只测完整回复，也无法发现流式兼容问题。

## 改动

- 侧栏和工作台对 queued/running 任务显示实时等待秒数。
- 15–90 秒显示“模型正在生成”；超过 90 秒提示可继续等待或取消后测试连接。
- 接入测试改为先测试真实短对话流式模式；不兼容时再测完整回复，成功后自动关闭流式并保存该设置。
- 新 API 配置默认流式，但只有本次连接测试验证后 worker 才会使用流式；旧配置未验证时先使用完整回复。
- 短对话总墙钟上限收紧为 120 秒；取消与超时继续终止本机请求子进程，远端停止/计费仍由服务商决定。
- 修复已同步到用户实际运行副本 `outputs/job-assistant 25`；数据目录保持 `job-assistant 25/data`。

## 验证

- Python 后端测试与 JavaScript 测试通过。
- 增加慢请求 70 秒 / 95 秒 UI 文案测试。
- 增加流式失败后自动回退完整回复的测试。
- Edge 现场确认：岗位读取 ready，最新快速分析已返回并同时显示在侧栏和工作台。

更新扩展后需重新加载并刷新页面。服务重启后重新配对。
