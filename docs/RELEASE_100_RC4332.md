# RC4.3.32 · 意图与对话验收修复测试版

本版针对 RC4.3.31 的五项验收。原版在真实 DeepSeek `deepseek-v4-pro` 上，意图请求因默认开启思考而在 220 个输出 token 内截断，非模板化请求落回旧规则，无法建单；此外回执未显示任务 ID，JD 原文指令也可能被恶意模型误判为用户授权。这些项目在原版不能判为通过。

DeepSeek [官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)注明思考默认开启，可用 `thinking.type=disabled` 关闭；本版的修改仅用于短 JSON 意图请求。

修复后，仅对 `api.deepseek.com` 的意图判断请求传入 `thinking: {"type":"disabled"}`。普通对话和后台专业任务不受这个参数改动影响。创建成功的回执显示完整任务 ID；未创建任务的自由回复即使错误声称已建单，也会被任务记录校正，并抑制这类临时流式文字。JD/岗位描述中的指令性文字、引号、否定、假设、第三方转述和单独的“好/可以”不能授权建单。未选岗位和隐私需重批时返回可操作原因。任务状态快照只脱敏自由文本，保留随机任务 ID 以便准确引用成果。

验收证据：使用虚构岗位、经历和临时 SQLite，真实 DeepSeek 请求对“结合我刚保存的经历，再对这个岗位做一次详细分析”返回 `analyze_job`；旧正则不识别该句，数据库只创建一个任务，回执含 ID，任务保留原话、当前岗位和已确认经历。六条误建单样例在真实意图调用中均返回 `chat`。真实对话中，虚构的本人经历得到 `fact_candidate=true`，未自动创建任务或写入长期事实。模型超时、无效 JSON、岗位切换、岗位版本变化、隐私失效及幂等建单另以合成服务和临时数据库复核。

工作台菜单在隔离的无用户资料 Edge 中打开，四个 `/` 项目均可读，未出现白块。真实 DeepSeek 对话能答出同岗位前文的虚构代号，并能从用户明确选中的分析结果复述唯一风险标记；另一岗位的不同标记没有进入回复。引用成果、跨岗位隔离、取消或确认经历、再次批准脱敏及旧结果过期还以 DOM 交互测试和临时 SQLite 流程核验。曾发现随机任务 ID 中连续数字被通用脱敏误遮蔽，现仅对引用结果的自由文本脱敏，结构化任务 ID 保持准确。没有操作用户当前的 Edge 会话或真实求职数据。

补充经历闭环的进一步检查发现：RC4.3.31 的 `prior_results` 会把未入档聊天回复摘要送入新分析提示词。RC4.3.32 将普通聊天排除出专业任务的历史策略材料，并要求报告在用户仅提及“刚才聊天补充”而未提供已确认事实时明确提示核对入档。虚构标记在保存前不再进入分析提示词；真实 DeepSeek 生成的未入档分析没有提到该标记，也提醒先核对入档并确认脱敏。保存且重新批准后，回归测试确认新分析提示词包含该事实。

限制：本次未在用户当前招聘网站页面重放完整侧栏流程；实际招聘站点、不同模型的意图识别率与耗时仍需同版安装后观察。聊天中提及但尚未核对入档的经历，不会变成长期已确认事实。RC4.3.32 仍是测试版，不是正式 v1。
