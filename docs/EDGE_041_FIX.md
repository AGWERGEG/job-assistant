# Edge 实时岗位识别修复 0.4.1

## 原因

2026-09-16 用户报告列表右侧已展开 JD，扩展显示“尚未识别到职位详情”。通过 Edge 原生可访问性树确认页面含职位描述标题、正文、匹配岗位卡片与“查看更多信息”链接，旧采集器仅依赖旧版 class，因此未定位到详情。

另观察到独立详情页显示“职位正文缺失或不唯一”。旧代码要求整段候选区域只有一个正文块，不能区分职位描述与其他模块。

## 修改

- 增加语义定位：从可见“职位描述”标题与相邻正文确定 JD 区域。
- 列表布局以详情中的“查看更多信息”链接解析岗位 ID，在列表中找到相同 ID 的卡片作为名称与公司来源；还须详情标题一致。
- 独立页面正文不唯一时，仅使用职位描述段，避免把公司介绍、推荐和招聘者信息合并到 JD。
- 薪资中出现自定义字体的 Unicode 私用字符时不猜数字；正文不可靠时提示核对。
- 新增无正文诊断：仅标签、类名和元素数量，可在侧栏“页面识别诊断”生成并复制。
- 最近点击的岗位 ID 与详情尚未一致时暂缓识别。

## 你需要操作

1. 解压 0.4.1，保存到固定目录。
2. 在 `edge://extensions` 更新已加载的扩展：若用原目录替换，点“重新加载”；若用新目录，移除旧扩展后加载新包中的 `extension` 目录。
3. 关闭旧侧栏，刷新 BOSS 职位页，再打开侧栏。只刷新本地工作台不会更新扩展。
4. 查看侧栏顶部是否显示 **0.4.1**，重新配对（如需要）。
5. 先关闭自动分析，点击不同岗位，确认侧栏标题/公司/正文绑定正常，再打开自动分析。
6. 如仍显示未识别，展开“页面识别诊断”，点“生成识别诊断”并复制。该报告不含简历、JD 正文、聊天、Cookie 或 URL 参数。

## 验证边界

已在用户 Edge 实際页面确认上述两种错误与可见结构。没有成功取得实际 DOM class 全量结构，也未替用户重载其已安装扩展，不能称修复版已完成真实 Edge 端到端验收。

使用按可见结构重建的合成 DOM 回归测试验证列表详情、公司绑定、标题/链接切换不一致、独立页多正文排除、隐藏内容和诊断去正文；共 10 项 JS 测试通过。后端没有修改，配对及协议沿用 v0.4。
