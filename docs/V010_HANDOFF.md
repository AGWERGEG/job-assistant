# v0.10 使用结构重构

2026-09-17。本轮为页面组织与操作衔接，不新增模型能力、不改数据schema、不增加依赖。

## 使用结构

- 继续聊：回到上次选定岗位或日常对话；首页只显示聊天、当前目标和最近三项后台任务入口。任务提交后不强制跳走；状态卡可直接查看对应岗位结果。完成项不是“未读”统计。
- 我的机会：左侧岗位列表，右侧按概览/简历/面试/记录分类。概览含岗位原文、公司证据与深度分析；简历集中编辑、验收、回填导出及历史版本；面试含准备、复盘和其结果；记录只显示当前机会事件，顶部注明全部机会累计统计。
- 我的档案：认识搭子、简历原文、偏好、脱敏审核、确认事实。未完成建档时默认进入此处，已建档用户默认继续聊。保留原表单，尚非完整分步向导。
- 设置：模型连接、扩展配对和数据管理。日常聊天不铺开配置；角色称呼仍随“认识搭子”放在档案入口。
- 简历版本对比默认折叠；后台任务结果不再混入所有短对话列表，短对话取消/重试保留在聊天中。

## 操作衔接

- 兼容已有#job、#task、view=interview/journey链接；对应结果打开正确岗位、正确分类。新增page/tab保持刷新后的视图。未知岗位回到日常对话，提示不存在。
- 页面内切换保留简历草稿、分岗位未发送聊天和面试笔记；不写浏览器持久存储。刷新/关页仍会丢失未保存草稿，已提交任务及验收稿在本机DB保留。
- 侧栏“正在浏览”和“正在聊”分开显示。无目标时点击三个快捷键会先核对当前页面、建档确认再发起任务；只读页面不会自动调用模型。已有目标时新页面不能自动替换目标。
- 页面身份暂缺或切到不相关页面时，可继续聊明确标出的旧目标；不把新页面注入聊天。页面相关快捷分析/简历/招呼保持暂停，切换目标需明确确认。同公司材料仍需用户保存。
- 公司材料入口折叠，文案按场景显示“补充这家公司的背景”/“用这个岗位作参考”。岗位提取器本轮未改变。

## 工程

web/workspace.js负责DOM布局、页面与机会分类导航、任务定位、最近结果。只移动原节点，不克隆表单或ID；app.js继续负责状态和API。server仅增加workspace.js静态路由和版本号。没有前端框架或构建流程。

测试命令：

```
python3 -m unittest discover -s tests -q
NODE_PATH=/路径/extension-test-deps/node_modules node --test tests/test_extension.cjs tests/test_workspace.cjs
```

## 验证

71项Python后端、32项扩展JS、5项工作台JS测试通过。新增覆盖老用户首页、新用户建档、旧链接路由、任务跨岗位定位、分类筛选、未保存草稿、首次快捷动作绑定及页面未知时固定目标聊天。

隔离虚构数据工作台实际浏览器验证：首页发起简历任务但不跳走 → 完成后点击结果 → 对应机会简历页 → 验收回填预览 → 刷新仍在同岗位/分类。没有调用付费模型，模拟耗时不是模型速度。Word/PDF渲染器未变更。

侧栏行为变更经合成测试，未代用户安装/重载新版Edge扩展完成实站验收。已有v0.9.1数据备份后原地启动v0.10.0；ZIP不含data/data-demo/密钥/数据库。

## 范围与后续

本轮完成组织和主要跳转，不把路线图全说成完成：完整分步引导、聊天就地确认进展、事实全局/岗位范围选择、已读结果、机会阶段管理、严格总超时和内容真实性防护均未新增。休息/入职结语沿用v0.9.1，隐私审核和用户手动投递边界不变。

重点验收：旧用户首页是否容易继续；侧栏第一次点击分析是否正确绑定；看B时明确仍聊A；任务入口是否直达对应机会；草稿切换是否保留；档案和设置是否容易找到。不要测试时误把真实数据目录清空。
