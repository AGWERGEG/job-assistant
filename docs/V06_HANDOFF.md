# v0.6.0 公司与岗位材料版

2026-09-17。替代0.5的“只理解岗位页”方案。主链路：确认目标岗位 → 查看同公司介绍/产品/招聘页 → 保存背景或对照JD → 对话使用公司资料 → 工作台核对证据。

## 本轮真实Edge观察

通过Edge原生界面检查有赞公司招聘页、独立职位页、公司介绍页：

- 公司招聘页为 /gongsi/job/<id>.html，分类页含数字职位类型路径；公司ID包含~字符。
- 公司招聘页右侧标题是“职位描述：”，旧采集器精确等于“职位描述”因此漏读。左侧卡片没有逐卡公司链接，需继承公司页身份。
- 独立页实测3个.job-sec-text，分别在.job-detail-section（364字JD）、.salary-info（79字）、.company-info-box（1108字介绍）；薪资/公司介绍应独立处理。
- 独立页运行0.5.1时仍出现正文不唯一。代码审查确认directCompany把所有层级公司链接混到一起，会被推荐公司污染；现在优先局部唯一名称，不再退回列表标题同步逻辑。正文与公司缺失现在分别提示。
- 公司介绍页有“公司简介”“产品介绍”栏目。产品列表实际显示有赞零售、微商城、教育、美业；另有高管简介、招聘者和工商资料，不属于本轮业务正文采集范围。
- 独立页同一文字中出现动态空白，标题判断已规范化空白和冒号。

以上为真实页面与结构检查，不等于新扩展已经在Edge端到端验收。Edge仍需加载0.6.0后刷新页面。本轮没有使用BOSS私有接口、Cookie或自动发送消息。

## 实现

1. extractor.js：岗位读取与公司读取分开；识别公司页、产品栏目、局部岗位卡片、招聘分类与筛选说明。公司标识从规范化BOSS链接获取，不能仅按名称合并。标题移除“收藏/招聘”展示后缀。
2. panel.js：公司ID明确的目标岗位跨标签、公司页、同行岗位浏览保留；另一岗位可“改为目标岗位”。手动保存当前公司资料/加入对照，异公司禁止合并或沿用旧目标发送。无法关联公司ID的旧布局保留0.5.1行为。
3. 公司数据：companies、job_companies、company_evidence三张表，schema6幂等迁移。证据保留来源URL（去参数）、企业自述标签、时间、截断标识与版本。没有联网检索。
4. 同页重复保存去重；更新保留旧证据，当前画像选取各来源/栏目最新版；同行JD按岗位标识保留。
5. 任务创建时保存公司背景快照。最多选取10条/约18000字符进入模型上下文，仍走privacy.py脱敏。保存公司材料不会自动调用模型。新增背景标记历史对话资料过期，旧任务原始快照不变。
6. worker指令要求区分企业自述/招聘表述/推测/未知，引用材料ID前8位；不可把分类数量当全部已读、不可据岗位数量推断离职率或编制。
7. 工作台新增“公司与业务材料”，可以核对正文、分类、读取条件、来源和时间。生成的业务理解仍通过对话/深度分析返回，并非确定性企业评级。

## 限制

- 公司栏目采用DOM可见性与语义标题定位，未对全部BOSS模板验收。折叠/溢出内容可能标为partial；只处理已加载文本，不自动展开/翻页，不读取图片文字。
- 产品栏目嵌套结构、复杂公司招聘列表可能还需适配；采集到0条时不能声称“已经读完公司”。
- 原始证据存本机；模型仅收到经脱敏的有界片段，链接保留在本地工作台以材料ID对应。
- 目标需先带有可靠公司ID。没有公司链接的页面只保留岗位能力，不能按名称猜关联。先确认新版识别的同公司岗位，再去公司介绍保存。
- 同名品牌不代表同一法律主体；仅表示同一个BOSS公司页面，企业主体关系尚无专门验证。
- 本版侧栏保留目标只限当前侧栏会话；关闭重开可以重新确认岗位恢复历史。
- 独立页已修复明确代码缺陷，但不声明所有独立页已彻底解决；失败可反馈0.6.0诊断。
- 真实模型内容质量/速度未在本轮测试；此前Codex额度限制记录仍保留。

## 新接口

- POST /bridge/company-save：配对、scope+seq、目标已确认；参数company含公司标识、来源、sections、jobs、categories、filters、可选peer。服务器验证同公司与来源。最多8个栏目/30卡片/20分类；没有完整JD的卡片不会伪装完整JD。
- POST /bridge/company-read：当前目标公司资料。
- POST /api/company：本地token，job_id；工作台显示证据。
