# v0.9.1 聊天结语与休息寄语

2026-09-17。替代v0.9关于本机祝福按钮和确认offer弹窗的交互说明。

## 当前行为

- 去掉“看看我们走过的这段路”、独立祝福弹窗及记录进展后的彩蛋开关。记录器仍保留，不再重复弹回顾。
- 工作台聊天栏与侧栏“面试与这一程”提供“休息 / 结束 · 寄语”，创建一次短文本模型任务；回复留在聊天历史。保留未发送输入，不清空聊天、不取消后台任务，也不意味着入职。使用现有模型配置和额度，仍受聊天通道排队约束。
- 用户在聊天中明确说“我已经入职了”“我正式入职了”等本人完成态陈述，创建closing_message。结果为模型祝福 + 本机统计快照 + 固定作者寄语。普通offer、未来计划、否定、疑问、引用、假设、第三人称不触发。
- 本地保守规则只识别有限明确句式，不承诺所有自然语言准确识别。漏识别时可直接说“我已经入职了”；歧义句保持普通聊天，不自动猜测。
- 点击记录器的已入职/offer不触发结语；聊天入职陈述不自动写入career_events，避免把新工作错误绑定当前浏览岗位。结语不锁定后续使用，仍能继续聊天。
- 统计仅来自既有确认进展与验收版本，创建任务时冻结；没有记录显示0并说明“未记录不等于未发生”。不声称统计覆盖全部求职经历，不把修改次数和验收版本数混淆。
- 作者寄语为固定文本，由本机追加，不交给模型；统计同样不交给模型编写，后续历史上下文去掉此固定尾部。寄语模型调用失败则按普通任务展示失败/重试，不伪装模型成功。
- 同一请求ID幂等；新发一条明确已入职消息会产生新的结语任务，尚无全局一次性/多求职周期管理。

## 工程

app/closing.py：明确入职判断、本机汇总、固定作者文案。新增rest_message/closing_message为短对话任务。统计快照存在原任务上下文的_closing_summary字段，safe_context出站移除，输出完成后拼接。旧milestones.py仅保留内部历史测试，旧/api/retrospective、/api/blessing、/bridge/blessing接口返回410，不再有面向用户入口。无数据库迁移、新依赖或独立模型调用层。
