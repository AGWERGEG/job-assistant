# RC4.3.2 智联与 58 Edge 兼容验收记录

日期：2026-09-22（Asia/Shanghai）

这是一份测试版增量验收记录，不代表 v1 正式发布。测试使用临时数据目录；没有读取 Cookie、调用招聘平台私有 API、自动发送或自动投递。

## 根因与修复

1. Edge 已加载扩展目录中的脚本可能仍是重载前的内存版本。源码同步后必须在扩展管理页重新加载，再刷新招聘页面，否则真实页面仍执行旧解析逻辑。
2. 侧栏保留了上次“已连接”显示，但本机 Bridge 已不可达。网络请求失败时现在会清除连接和就绪状态，显示重新连接提示，不再保留误导性的连接标记。
3. 智联当前列表页把岗位摘要和“职位描述”正文拆在不同容器。旧通用选择器会在正文容器里寻找标题，并可能把发布者文字误当公司。现在按当前页面结构分别绑定唯一岗位摘要、唯一详情链接、标题、已验证公司链接和标题恰为“职位描述”的正文卡；字段缺失或冲突时拒绝采集。
4. 58 真实岗位 URL 使用 `/zpshengchankaifa/<岗位ID>.shtml` 一类分类路径，且页面面包屑的 `h1` 不是岗位名。现在从 `.pos_info .pos_name` 读取标题，从唯一数字公司链接读取公司，从 `.pos_description .posDes` 读取正文；不再用分类标题或附近文本猜测。
5. 不同招聘站可能出现相同裸岗位 ID。侧栏和 Bridge 现在使用 `source_site + job_key` 作为身份，并核对 URL 中的站点与岗位 ID，避免跨站串岗或恢复错误目标。

## 已获得的真实 Edge 证据

- 智联真实列表/详情双栏页成功读取当前岗位：`技术支持工程师`，公司：`浙江保融科技股份有限公司`，来源岗位：`CC451832010J40155948108`。侧栏“岗位与资料”卡与页面右侧详情一致。
- 智联另一真实岗位也曾成功读取：`售前支持工程师`，公司：`正元智慧集团股份有限公司`。薪资和“HR · 公司”发布者文字没有进入标题或公司字段。
- 58 在进入登录态前已确认真实页面结构：岗位名位于 `.pos_info .pos_name`，正文位于 `.pos_description .posDes`，公司使用 `qy.58.com/<数字>/` 链接。旧逻辑把分类面包屑“广阳普工/技工招聘”当标题，修复后的真实结构夹具不再发生该错误。
